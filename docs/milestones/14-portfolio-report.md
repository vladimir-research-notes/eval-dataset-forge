## The question this milestone had to settle

Milestone 13 measured that a release is not reproducible from its inputs and seed alone: the
build environment is an input, because `scikit-learn`'s presence resolves near-duplicate
detection to `tfidf` rather than `jaccard`, and that changes `eval_id`. It then corrected the
sentence that said otherwise.

It corrected it in **one** file. `REPRODUCE.md` is generated by `render_reproduce()` and pinned
by a test, so a false sentence in it is a failing test. The identical false sentence sat
untouched in `README.md`, `docs/METHODOLOGY.md`, and `docs/PLAN.md` §4 — three files no test had
ever read.

> **A generated artifact is enforced. Prose is not.** A claim written in Markdown has no way to
> fail, so it does not fail, so it rots.

The repository's own quality bar says every major claim must be backed by a test, a reproducible
command, a result table, a documented limitation, or an explicit non-goal. Nothing checked that
the backing existed. So: what is the checkable surface of a document, and what is honestly
outside it?

### 1. The lint's first run found the sentence in exactly three files

`retired-claims` bans a sentence a milestone measured false from live prose. On its first run it
flagged `README.md:51`, `docs/METHODOLOGY.md:39`, and `docs/PLAN.md:112`, and nothing else. All
three are fixed. The docs that *quote* the sentence in order to refute it — `LIMITATIONS.md`,
`INTEGRATION.md`, `RESULTS.md` — were correctly silent.

**The lint does not verify the fact.** `tests/test_contracts.py` does, by building the same corpus
under both detectors and comparing `eval_id`. The lint only stops the retired phrasing from being
typed again into a file no test reads, and a test asserts that behavioural test still exists.

### 2. A number is not a claim until it names the command that produced it

`docs/RESULTS.md` reports the `qa_toy` difficulty calibration permutation p-value as **0.789**.
`evalforge audit` on the same fixture, at the same seed, prints **0.777**.

| command | `--resamples` default | permutation p |
|---|---|---|
| `evalforge difficulty` | 10000 | **0.789** |
| `evalforge audit` | 2000 | **0.777** |

Same fixture, same seed, same statistic — ρ = −0.080 in both. Neither document was mistaken, the
gap is the permutation test's Monte-Carlo error, and a reader comparing them has no way to
discover why they differ. Every claim in the ledger therefore carries the command that produces
it, `check_claim_commands` verifies that column names a command that exists, and
`test_the_two_p_values_are_the_same_statistic_at_different_resample_counts` pins the measurement.

### 3. Two published figures had no command that could produce them

That check earned its keep before it was finished. The first draft of `pooled_blocks_jaccard`
cited `evalforge audit --near-method jaccard` — a flag that did not exist.

`docs/RESULTS.md` and `docs/DEDUPLICATION.md` have published Jaccard recall and block counts since
Milestone 4. `run_audit` called `find_duplicates` with `near_method="auto"`, so the only way to
reproduce those numbers was to **uninstall scikit-learn**: the installed packages chose the
detector, and nothing let an operator choose it instead. Milestone 13's `Environment` section
*described* that; it could not *control* it.

`evalforge audit --near-method {auto,tfidf,jaccard}` now pins the detector. `auto` remains the
default and changes nothing — `test_near_method_defaults_to_auto_and_changes_nothing` pins that
too. On `bio_toy` the two detectors disagree (one near-duplicate cluster under `tfidf`, zero under
`jaccard`), which is why the flag had to exist rather than being a convenience.

**Deliberately not done:** `evalforge release` still resolves `auto`. Pinning a *release*'s
detector means deciding whether the method enters `eval_id`'s inputs, which is a Milestone 10
identity question, not a documentation one. It is raised in the review note.

### 4. A phrasing lint cannot separate a claim from its correction — measured, then shipped disabled

`sklearn_is_an_accelerator` is a true proposition to retire: `docs/PLAN.md` §3 called scikit-learn
an *optional accelerator with a pure-Python fallback*, and Milestone 13 showed it is a different
detector. Run over the live documents as this milestone found them:

| | count | which |
|---|---|---|
| documents flagged | 2 | `docs/LIMITATIONS.md`, `docs/RESULTS.md` |
| flagged documents that **assert** it | 0 | both quote it in order to refute it |
| documents that **do** assert it | 1 | `docs/PLAN.md` §3 |
| of those, flagged | 0 | the phrase spans a line break the pattern cannot cross |

**Precision 0/2, recall 0/1.** It flags exactly the two documents that disown the claim and misses
the one that makes it, because a correction must use the same words as the error. Run against the
corrected documents it flags three, and the third is `docs/CLAIMS.md` — the document that exists to
explain why the rule is disabled.

The rule ships in `CANDIDATE_RETIRED_CLAIMS`, in no enforced check, with a test asserting nothing
picks it up. This is Milestone 13's precedent exactly: `difficulty_is_calibrated` is in the
requirement registry and in no profile. `docs/PLAN.md` §3 and the `pyproject.toml` comment were
fixed by **reading them**, which is what actually found them.

## Use is not mention

Both false positives the auditor ever produced were use/mention errors, and both were found by
running it rather than by reasoning about it.

- **`docs/RESULTS.md`** opens its quotation of the retired sentence on one line and closes it on
  the next. The first draft of `_asserted` counted quote characters per *line*, so it read the
  continuation as an assertion — producing its only false positive on the document most careful to
  disown the claim. The unit is now the **paragraph**: quotations wrap across lines, not across a
  blank line.
- **`docs/DATASET_CARD.md`** contains a literal `[text](url)` inside backticks, as an example of the
  Markdown the card generator must escape. `check_links` chased it to a file named `url`. Code spans
  are now masked before any check that reads English. That is the same use/mention error one level
  down, for links rather than sentences.

`RetiredClaim.cited_in` — the escape hatch naming files allowed to assert a retired claim anyway —
is **empty**, and a test asserts it stays empty. An allowlist that stays empty is one nobody can
quietly grow.

## The auditor is a defect detector, and it is scored like one

A checker that reports zero violations is indistinguishable, on that number alone, from a checker
that looks at nothing. It is the mirror image of Milestone 12's flag-everything control: there, a
detector that asserts *everything* earns recall 1.000; here, a detector that asserts *nothing*
earns zero violations. Both numbers are free.

So `tests/test_docs.py` plants a defect for every check and asserts the check fires — a broken
link, an invented subcommand, a renamed flag, a stale test count, a fixture id no fixture holds, a
retired claim retyped, a ledger row the code does not reproduce, a drifted README, a claim citing a
command that does not exist, an orphaned entry point. `test_the_audit_actually_looked_at_something`
asserts the coverage counters are non-trivial, because a clean report over zero documents is the
checker that looks at nothing.

**The first thing the new check caught was drift this milestone had itself created.** Adding two
tests to `tests/test_audit.py` invalidated the `# 47 tests` comment on `docs/RESULTS.md:699`
within minutes of the checker existing.

## Live documents and historical records are different things

`README.md` and `docs/*.md` state what is true now. `docs/milestones/*.md` and
`docs/review_notes/*.md` state what was true at a commit — `docs/milestones/12-smoke-audit.md`
records `# 1706 tests` and is right about the commit it describes. Checking counts against history
would force rewriting the record to match the present, which is the one thing a record must never
do.

Counts and retired claims are therefore checked against live docs only. Links, commands, and
referenced paths must work wherever they appear, and are checked everywhere.
`test_test_counts_are_not_checked_against_the_historical_record` pins the distinction.

## What no check here can supply

- **It does not check that the code is correct.** The ledger proves the documentation agrees with
  the code. That the code is right is what the rest of the suite is for. A number can be wrong in
  both places and pass every check.
- **Retired claims are phrasings, not propositions.** A paraphrase evades the pattern. Recall over
  "false sentences in this repository" is unmeasurable, because unlike the fixtures — whose defects
  are planted and enumerated in `defects.yaml` — no ground-truth list of false sentences exists.
- **Only fenced `bash`/`sh`/`shell`/`console` blocks are parsed.** An `evalforge` invocation written
  inline in prose is unchecked.
- **`evalforge` is never executed.** It reaches `PATH` only after `pip install -e .`, which the
  offline suite does not do. `check_entry_point` verifies the declared target imports and is
  callable; it does not prove the binary runs.
- **`site/*.html` is not audited at all.** It restates the docs' claims and nothing verifies the
  restatement.
- **Most prose states no number and quotes no retired claim.** This is a lint over the checkable
  surface, not a proof of honesty.
