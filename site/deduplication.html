Deduplication

Duplicates inflate apparent sample size and reward memorization. We detect them at three increasing levels of tolerance, and always report the method and measured similarity per finding.

1 · Exact (no false positives)

sha256 hashing of the relevant field(s): duplicate example_ids (always an error), byte-identical input, byte-identical expected_output, and duplicate source records.

2 · Normalized-text

Examples that differ only in formatting. Conservative normalization (lowercase, collapse whitespace, NFKC, strip punctuation-only differences), then hash-compare. Catches casing/whitespace/smart-quote variants; does not try to merge genuine paraphrases.

3 · Near-duplicate (heuristic)

methodsignalneeds
Token n-gram Jaccardset overlap of word n-grams (default n=3), threshold ≥0.8pure Python
TF-IDF cosinevocabulary-weighted similarity for paraphrasesscikit-learn (optional)

A cheap blocking step (shared rare n-grams / MinHash-style bucketing) restricts pairwise comparison to candidates so the check stays CPU-tractable; brute-force O(n²) is the reference implementation for the small fixtures. When scikit-learn is absent, TF-IDF falls back to Jaccard.

Near-duplicate detection is heuristic: it misses deep paraphrases with low lexical overlap and can flag similar-but-distinct items. Embedding-based semantic dedup is intentionally out of scope for the offline build (see Roadmap).
