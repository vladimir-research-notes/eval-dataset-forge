Deduplication

Audit dimension #2: does this dataset say the same thing more than once? Duplicates inflate apparent sample size, reward memorization, and break the independence assumption the bootstrap confidence intervals rest on — a benchmark holding forty copies of one item has fewer effective examples than its row count claims.

A ladder of three stages

Each stage is strictly more tolerant — and strictly less certain — than the one before.

stagecertaintycatches
1 · Exactexactbyte-identical prompt and gold answer
2 · Normalizedexact given the normalizationprompts differing only in case / whitespace / punctuation / Unicode form
3 · Nearheuristicparaphrases, edits, reorderings

The stages are disjoint by construction: a normalized finding always merges at least two distinct raw contents, and a near finding never covers a pair the earlier stages resolved. The three lists partition the evidence rather than triple-counting it.

Nothing is ever deleted. Only exact clusters nominate an example for removal; dropping a heuristic match on the tool's say-so would silently delete a legitimate example.

1 · Exact (no false positives)

Dedup identity is the pair (input, expected_output) — not example_id, not split, not metadata. Method: sha256(input + NUL + canonical_output(expected_output)). The NUL separator stops ("ab","c") and ("a","bc") from colliding; canonical_output is sorted-key JSON, so {"a":1,"b":2} and {"b":2,"a":1} agree while the string "4" and the integer 4 do not.

Two related signals stay deliberately separate: a shared prompt with differing answers is a label conflict, not a duplicate; and several examples from one source_id are statistically dependent rather than redundant (the fixtures' src-shakespeare legitimately yields distinct questions about Romeo and Juliet and Hamlet).

2 · Normalized

NFKC, case folding, punctuation → space, whitespace collapse. Applied to the prompt only — the gold answer must still match canonically. Punctuation-folding a code reference solution or a JSON rubric would merge two materially different answers.

3 · Near-duplicate (heuristic)

Stages 1–2 ask “are these the same string?”. Stage 3 asks “are these the same item?”, which no lexical method decides correctly. Its output is a ranked review queue, never a verdict. Both methods share one feature space — the word n-grams of the prompt — and differ only in weighting.

methodsignalneedsproperty
jaccardunweighted set overlap of word n-gramspure Pythondataset-independent; scores template/stopword boilerplate high
tfidfcosine of idf-weighted n-gram vectorsscikit-learn (optional)down-weights corpus-common terms; score depends on the corpus

auto prefers TF-IDF because it dominates Jaccard on the fixtures — never fewer true positives, never more false ones — and falls back to Jaccard when scikit-learn is absent. The resolved method is recorded on every finding, so a report is self-describing.

The answer gate

A candidate pair must also agree on its gold answer. A paraphrased prompt with a different gold answer is not a duplicate — it is a mislabeling or two genuinely different questions, both the label audit's business. The gate is not cosmetic: without it, the two highest-scoring non-duplicate pairs each outrank a real planted duplicate.

Calibration

Thresholds were chosen by sweeping the 56 committed fixture examples and taking the knee of the precision/recall curve. Both methods land at 0.30; they stay a per-method mapping because the two scores are not on a common scale. Counted pairwise, before single-linkage clustering, against the 5 planted pairs:

thresholdJaccard TP / FPTF-IDF TP / FP
0.253 / 54 / 5
0.30 (default)3 / 24 / 3
0.352 / 23 / 2
0.452 / 12 / 2
0.601 / 01 / 0

The defaults favor recall: a missed duplicate silently leaks across splits, while a false one merely pins two examples into the same split. The n-gram width is the other knob — n=1 (bag of words), because a paraphrase destroys contiguous n-grams long before it destroys the vocabulary. Widening to n=2 cuts Jaccard recall from 3 planted pairs to 1.

These thresholds are tuned on 56 synthetic examples and the numbers are in-sample. Re-calibrate on your own data. Jaccard at 0.30 is permissive for short, stopword-heavy prompts (no stopword list, no stemming); prefer TF-IDF, whose idf term becomes more selective as the corpus grows.

Known limitations

Each is asserted by a test, so a future improvement cannot silently invalidate this section.

  • One planted paraphrase is unreachable by any lexical threshold. ret-001~ret-002 scores 0.286, while ret-006~ret-009 — boiling vs freezing point of water, not a duplicate — scores 0.504. The non-duplicate ranks above the duplicate, so no threshold admits the first without the second. Separating them requires semantics.
  • Template questions are a standing false positive. qa-012 (“Who wrote the play Hamlet?”) joins the Romeo-and-Juliet cluster: same template, same gold answer, so neither the score nor the answer gate excludes it. It is independently flagged as a duplicate source record — the two channels agreeing is the intended design.
  • Single-linkage clustering is transitive. A chain of pairwise-similar items can merge into a cluster whose endpoints are dissimilar. Mitigation: the reported similarity is the weakest edge in the cluster, an honest lower bound.
  • Deep paraphrases with low lexical overlap are invisible — not because the threshold is wrong. Embedding-based semantic dedup is intentionally out of scope for the offline build (see Roadmap).
  • Comparison is brute-force O(n²). The blocking / MinHash bucketing a large corpus would need is deliberately deferred, not claimed.
  • Under TF-IDF, a duplicate report does not compose. The idf term is computed over the collection, so a near-duplicate verdict is a property of a pair and its corpus: sim(saf-004, saf-007) is 0.2866 inside safety_toy and 0.3438 pooled, straddling the 0.30 threshold with neither prompt changed. Auditing shards and unioning the findings is not auditing the union — the five fixtures hold 45 independent blocks apart and 44 pooled — and appending unrelated data can move an untouched example's block, hence its split, hence a release's eval_id.
  • The jaccard fallback is immune, and that is the problem. Raw set overlap has no idf, so both properties above hold under it. The two methods return different duplicate reports, not the same report at different speeds: on bio_toy, bio-001 ≈ bio-002 clears 0.30 under TF-IDF and not under Jaccard. Since auto picks TF-IDF iff scikit-learn is importable, installing an "optional accelerator" changes which examples a release holds out. Every release records dependence.near_method; see Integration contracts.

Status

Implemented and tested. python3 -m pytest -q → 267 passed, of which tests/test_dedup.py contributes 99: primitives, exact recall scored against every fixture's defects.yaml, stage disjointness, the answer gate, the scikit-learn fallback, determinism, and regression tests that pin the two documented failure modes.

Open questions

  • Would a light stemmer (produces/producing, bake/baking) lift recall enough to justify the over-merging risk on short items?
