Leakage & contamination

Audit dimension #4: can a system score well here without doing the task? Four checks look for four distinct paths, each emitting exactly one LeakageKind.

checkmodulecertaintycatches
1 · Cross-split overlaptrain_test_overlap.pyinherited from dedupthe same item in two splits
2 · Answer-in-promptanswer_in_prompt.pyheuristicthe gold answer quoted in its own prompt
3 · Reference n-gram overlapngram_overlap.pyexact given the widtha prompt verbatim in a reference corpus
4 · Retrieval contaminationretrieval_overlap.pyexactannotation artifacts; shared gold passages

Unlike the deduplication ladder, whose three stages are disjoint by construction, these four channels overlap on purpose. A test example copied verbatim from train is a cross-split exact duplicate and a full n-gram overlap against the train reference. Agreement between independent channels is corroboration, not double counting — and the payoff is measurable, as the corroboration section shows.

Nothing is removed and nothing is a verdict. find_leakage() produces evidence; the split builder decides what to do about it.

1 · Cross-split overlap

Filters the dedup ladder's clusters down to those spanning two or more assigned splits, inheriting each stage's certainty exactly: exact clusters yield exact findings, near-duplicate clusters yield heuristic ones. dev/test overlap counts as the same defect as train/test — tuning on an item, then scoring on it. unassigned is excluded: an example not yet placed in a split cannot leak across one.

Source-level dependence is a separate channel. Two examples from one source_id are not duplicates — the fixtures' src-shakespeare yields distinct questions about Romeo and Juliet and Hamlet — but they are statistically dependent, and scattering them across splits leaks source-level information. Reported on its own channel, because “dependent” and “duplicated” call for different remedies: the first wants a source-grouped split, the second a deletion.

2 · Answer-in-prompt (heuristic)

The gold answer, quoted inside its own prompt. Measured as containment — the fraction of the answer's word n-grams that occur in the prompt — which is deliberately asymmetric: it asks “how much of the answer is in the prompt?”, not “how similar are they?”. A one-sentence answer fully quoted inside a thousand-word prompt scores 1.0, where a symmetric Jaccard would score near zero.

expected_output may be a string, a scalar, a doc-id list, or a rubric dict. Searching a serialized JSON blob would never match, so the value is walked and each leaf string checked with its field path recorded. That is what finds agent-004: the leak is in the reference_solution field of a two-key dict, not in the answer as a whole.

n=2 is the only width that recovers both planted leaks without a false positive, and the default threshold sits in the middle of a plateau rather than on a knife edge: the whole band [0.4, 0.6] gives the identical answer, because the weakest true positive scores 0.600 and the strongest non-leak 0.333.

The rejected widths fail for opposite reasons, both pinned by tests:

  • n=1 cannot tell a quoted answer from a prompt that shares its vocabulary — which every well-posed question does. agent-011's answer "return sorted(arr)" scores 0.667 against a prompt that merely describes returning a sorted arr; qa-013's "Pacific Ocean" scores 0.5 because the prompt contains the word ocean.
  • n=3 loses agent-004 (0.25). A paraphrased quotation keeps its bigrams long after its trigrams are gone.

Answers shorter than n are compared at their own width, so the one-token gold answer "Berlin" is found by a unigram match while longer answers keep bigram discipline. Every finding records the width it fired at.

The label-vocabulary guard

In a classification dataset the gold answer is a class name, and a prompt that names its own label set (“should the assistant comply or refuse?”) would be flagged on every row. A candidate must be short (≤ 2 tokens), repeated (≥ 3 times), and — the load-bearing condition — the candidate set must cover ≥ 50% of the dataset. Repetition alone is not enough: without the coverage test, qa_toy's "William Shakespeare" (3 occurrences, 21% coverage) would be dismissed as a class label.

On the fixtures the guard fires on safety_toy only, taking {comply, refuse}, and changes no result there. Its value shows on data the fixtures do not contain: on a synthetic sentiment set whose prompts read “Is review #N positive or negative?”, it takes the finding count from 8 of 8 examples to zero. Nothing is suppressed silently — the chosen vocabulary is printed on the report. Its cost is a true negative: a genuinely leaked class label in a genuine classification dataset goes unreported.

3 · Reference n-gram overlap

The standard decontamination signal: flag an evaluation prompt sharing a word n-gram with a reference corpus. Default reference is the train split, default targets dev and test; any external corpus can be supplied instead. n=8 — the low end of the published 8–13 band — and the rule is the standard one: any single shared 8-gram is the flag, with containment reported as strength.

Why n=8 and not n=5

At n=5 the same rule fires on shared boilerplate:

flagged at n=5containmentwhy
qa-002, agent-006, bio-006, saf-0051.000genuine verbatim duplicates
qa-0040.167shares “who … the play romeo and juliet”

saf-0030.125shares “chocolate chip cookies at home”

Four spurious findings, each a shared template rather than a shared item. At n=8 only the four verbatim duplicates survive, all at containment 1.000. Prompts shorter than n are compared at their own width and the finding says so; without that clamp, an 8-gram check would silently report “no contamination” for exactly the short items most likely to be duplicated verbatim.

An honest null result: on these fixtures this channel finds nothing the exact overlap channel does not. Its four findings are exactly the four identical cross-split pairs. Every planted overlap is either identical (caught twice) or a paraphrase (invisible to 8-grams, by design). The channel earns its place on datasets with an external reference corpus, where no dedup stage can help — which the fixtures cannot demonstrate. The redundancy is asserted by a test rather than hidden.

4 · Retrieval contamination

Keyed on the presence of metadata.retrieval.docs, not on the task family, so a QA item shipping retrieved context is audited too. Two exact signals.

Annotation artifacts in passage text. A passage carrying [ANSWER: Mars] or ground truth = has had the annotation pipeline leak into the corpus; a retriever can rank by the marker instead of by relevance. The pattern is curated — a label word immediately followed by : or =, the shape of a machine-written annotation rather than of an English sentence. Over every passage and every prompt in all five fixtures it matches exactly once, on the planted artifact in ret-003/d5.

A gold passage shared across splits. The same passage text in a training example and a test example — under different doc_ids, which is how it evades id-level checks — means the held-out evidence was never held out. Distractors are not flagged: reusing an irrelevant passage is normal corpus construction, so a cluster counts only when the passage is relevant for at least one example it appears in.

An earlier draft of docs/LEAKAGE.md proposed flagging “the gold answer string embedded in a passage”. For retrieval data that check is wrong: a relevant passage containing the answer is the definition of relevance, so it would fire on every correctly labelled example and discriminate nothing. The prompt-side analogue is real, and check 2 owns it.

Corroboration between independent channels

ret-001~ret-002 is planted as a cross-split overlap and is provably unreachable by check 1: the queries are a deep paraphrase, and Milestone 4 established that a genuine non-duplicate in the same fixture scores strictly higher, so no threshold admits one without the other.

The passage-level check recovers the same pair anyway, because both examples cite the identical gold passage under different ids. Two independent channels, one defect, one of them blind to it. This is the argument for keeping the channels non-disjoint.

The disputed finding

agent-003~agent-004 straddles train/test with an identical reference solution, the prompts differing only by an appended hint. defects.yaml files that pair under leakage: answer_in_prompt, so the dedup layer scores it a false positive — but as cross-split overlap it is arguably a true one. The disagreement is recorded by a test rather than resolved by editing ground truth, and is flagged for human review.

We can only measure overlap against text we are given. Contamination against unseen (e.g. private pretraining) corpora is undetectable here — absence of a flag is not evidence of no contamination. This is a property of the problem, not a gap in the implementation.

Known limitations

Each is asserted by a test, so a future improvement cannot silently invalidate this section.

  • Cross-split overlap inherits every dedup blind spot. A cross-split paraphrase invisible to the near-duplicate stage is invisible here.
  • Answer-in-prompt is lexical. It sees a quoted answer and misses an entailed one, and cannot distinguish a leak from a legitimate restatement (“extract the year 2020 from: … in 2020 …”).
  • The label guard trades a false positive for a false negative. A genuinely leaked class label in a genuine classification dataset is not reported. The guard prints what it ignored.
  • Paraphrased duplicate passages are not detected. retrieval_toy's d13/d14 state one boiling-point fact two ways. Passage matching is exact after normalization, and no threshold separates those two from unrelated passages without semantics.
  • The artifact marker is a curated list, not a detector. A corpus that leaks its labels under a convention we did not think of passes clean.
  • Comparison is brute-force. The blocking step a large corpus would need is deliberately deferred, not claimed.

Status

Implemented and tested. python3 -m pytest -q → 378 passed, of which tests/test_leakage.py contributes 111: containment primitives, the calibration sweeps above, the label guard demonstrated on a synthetic classification set, recall against every fixture's defects.yaml, the corpus-wide artifact-marker false-positive check, and regression tests pinning each documented failure mode.

Open questions

  • Should agent-003~agent-004 be recorded in defects.yaml as a cross-split overlap as well as an answer-in-prompt leak? It is currently counted against both the dedup and the leakage layers as a false positive.
  • Is the label-vocabulary guard's coverage threshold (50%) right, or should the release builder require it to be set explicitly per dataset?
  • The n-gram channel is redundant on the fixtures. Is a small public-safe external reference corpus worth committing so it can be exercised end to end?
  • Should dev/test overlap be reported at a different severity from train/test, rather than sharing one kind?
