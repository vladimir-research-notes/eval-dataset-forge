The audit pipeline

A linear sequence of separable, independently tested stages. Validated examples in; typed findings, distribution summaries, and prioritized recommendations out.

Stages

load → validate → dedup → leakage → label-audit → difficulty
     → splits → statistics → report
stagewhat it checksexact / heuristic
validate M3schema, ID uniqueness, PII/secrets, qualityexact + heuristic
dedup M4exact, normalized, near-duplicateexact + heuristic
leakage M5train/test overlap, answer-in-prompt, n-gram, retrievalexact + heuristic
label-audit M6missing, conflicting, ambiguous, format, adjudicationexact + heuristic
difficultytransparent heuristic score + bucketsheuristic
splitssizes, distributions, cross-split leakageexact
statisticsbootstrap CIs, paired comparison, ranking stabilityresampling

Design principles

  • Findings, not verdicts. The pipeline never silently mutates data or certifies a dataset as "clean" — it emits findings and recommendations for a human to act on.
  • Exact vs. heuristic is always labelled. Every finding records the method used and (for heuristics) the measured score.
  • Determinism. Fixed input + seed ⇒ reproducible output.
  • Offline & CPU-only. No stage needs a network or GPU.

evalforge audit \

Status

The first three stages — validate (Milestone 3), dedup (Milestone 4), and leakage (Milestone 5) — are implemented. Note that dedup and leakage are separable but not independent: the leakage stage consumes the dedup ladder's clusters to find cross-split overlap, and the audit pipeline passes it the report it already computed rather than paying for it twice. The remaining stage modules land in Milestones 6–9; the report and end-to-end smoke audit are assembled in Milestones 11–12.
