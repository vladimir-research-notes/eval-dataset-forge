Statistical uncertainty & ranking stability

Every earlier stage describes the dataset. This one describes what the dataset can support — and for a benchmark of the size most teams actually build, that is much less than its leaderboard implies.

The headline. The textbook bootstrap resamples examples, which assumes examples are independent. On a corpus with duplicates they are not: a deterministic system scores every member of an exact-duplicate cluster identically, so the within-cluster correlation is 1 by construction. A coverage simulation with known ground truth shows the i.i.d. interval covering 88.2% of the time against a nominal 95%. Resampling duplicate blocks instead recovers 93.7%. The pooled corpus's 56 examples are worth ≈ 36 independent ones.

1. The resampling unit is a first-class parameter

Every bootstrap implementation encodes an assumption about what "a fresh dataset" is made of. Here it is named rather than hidden, and both are always computed so the report can quote the ratio of their variances — the design effect.

block (default)one duplicate / source blockblocks are independent

Blocks come from splits.blocks.duplicate_blocks — the same union-find components the adversarial split strategy uses. The two stages therefore agree about what a dependent group is, and both inherit the near-duplicate stage's recall bound.

Coverage, against known ground truth

A confidence interval's only testable property is that it contains the true parameter 95% of the time. That sentence needs a true parameter, which a real benchmark never has — so we simulate one. 44 blocks with the pooled corpus's exact size profile (34 singletons, 8 pairs, 2 triples = 56 examples); each block's outcome is Bernoulli(p) and is copied to its members. 3000 trials, B = 999, Monte Carlo error ±0.004.

2. The bootstrap "win fraction" is not a p-value

The rule "A beats B if A wins ≥ 95% of the bootstrap resamples" is a one-sided 95% statement, applied post hoc in whichever direction the data happened to favour. Its two-sided size is therefore ≈ 0.10. Measured under a true null (n = 56, two independent Bernoulli(0.7) systems, 3000 trials, nominal α = 0.05):

decision ruletype-I error
win fraction ≥ 0.95, used two-sidedly0.114
win fraction ≥ 0.9750.057
cluster-aware sign-flip test, p ≤ 0.050.029

eval-dataset-forge reports the win fraction — readers expect it — and decides with the sign-flip permutation test. significant reads the Holm-corrected p-value and never the win fraction.

The sign-flip test, and its honest cost

Under the null that A and B are exchangeable, the paired difference is symmetric about zero, so flipping signs leaves the distribution unchanged. Signs are flipped at the block level: flipping per example would silently restore the independence assumption the cluster bootstrap exists to remove. The p-value uses the Phipson–Smyth (1 + count) / (1 + B) estimator, so it is floored at 1/(1+B) rather than claiming an unsupportable p = 0.

The cost is in the table above: at nominal 0.05 the test rejects only 0.029. It is conservative on paired binary scores, because most examples are ties and the null distribution is coarse. Reported, not hidden.

Two nulls can disagree, and that is not a bug. On the demo, sys_a vs sys_c has a 95% CI of [+0.033, +0.411] — excluding zero — and a sign-flip p = 0.051. The bootstrap interval is centred on the observed effect; the sign-flip null is centred on zero and preserves each block's |difference|, so the effect's own magnitude enters the null's spread (null sd 0.101 vs bootstrap sd 0.096). The permutation test is the more conservative near the boundary, and it is what significant reads. The report warns about the disagreement rather than resolving it by quoting the friendlier number.

And a p-value is itself an estimate: p = 0.051 at B = 2000 carries a Monte Carlo standard error of 0.005. Every comparison reports p_mc_se, and p_is_borderline fires when the verdict is set by the seed rather than the data. Multiplicity across the K(K−1)/2 pairs a leaderboard implies is handled by Holm–Bonferroni, which controls family-wise error under arbitrary dependence between the tests.

3. Deletion explains fragility better than resampling

Resampling answers "would a different sample have produced this leaderboard?". Deletion answers a sharper question: what is the smallest set of examples whose removal erases A's lead over B? No seed, no interval — an integer, computed exactly.

The argument is two lines. Deleting a set of units leaves mean (S − R) / (N − M), and the sign of a mean does not depend on its denominator. So the example counts of the deleted units are irrelevant: minimising the remaining mean over all k-unit deletions is exactly maximising R, which the k largest unit sums achieve. Greedy is optimal, and it is brute-forced against every subset on small inputs in the test suite.

The two examples are one block. This is a mechanism, not a coincidence: a cluster of size m contributes m times to a margin while carrying one item's worth of information, so duplicates are the highest-leverage items in any close comparison. A benchmark whose winner is decided by one duplicate cluster is not measuring what its leaderboard claims to show.

The verdict, and the interval method

StatsReport.ranking_resolved is a single bit, true only when three independent conditions hold: effective sample size ≥ 30, the leader holds first place in ≥ 95% of resamples, and its margin over the runner-up survives Holm correction. On the committed fixtures it is False, and evalforge stats --fail-on-unstable-ranking exits 1.

Ties are common, not exotic — a mean over 56 examples takes one of 57 values. Top-1 frequency splits a tie's credit evenly rather than breaking it by name (which would hand an alphabetical system free first-place mass); exact-order frequency counts only strict orderings; tie_fraction reports how often it mattered (8.8% of block resamples on the demo, 35% on qa_toy alone).

The default interval is the percentile one. BCa is available and is not the default, because it is not uniformly better:

At p = 0.95 on 56 examples the bootstrap distribution is near-degenerate: 5.7% of trials cannot compute the bias correction at all (the interval falls back, and method records bca->percentile rather than lying), and the ones that can are corrected in the wrong direction. An interval method that is better on average and worse exactly where the data is thinnest is offered, not imposed.

Input format

One JSON object per line, in either shape; they may be mixed.

{"example_id": "qa-001", "system": "sys_a", "score": 1.0}
{"example_id": "qa-001", "scores": {"sys_a": 1.0, "sys_b": 0}}

Alignment is strict. A score for an example the dataset does not contain, or an example no system scored, raises. The alternative is to impute, and every imputation of a missing eval result is a silent decision about a system's score on an example it may have crashed on.

Limitations. The demo's system scores are synthetic — a Rasch simulator, so the machinery runs offline and the coverage tests have a true parameter. The block structure is real; the systems are not, and no claim about any model is made from them. The cluster bootstrap corrects only for dependence the dedup ladder can see: ret-001/ret-002 is a paraphrase pair no lexical threshold reaches, so it yields no block edge and the reported design effect is a lower bound. The percentile bootstrap under-covers at extreme accuracies whatever the unit (0.910 at p = 0.90 on 56 i.i.d. examples). minimum_detectable_effect and required_n are normal approximations to a trinomial quantity — a scale, not a promise. The ICC is estimated and can come out negative on data with no clustering; it is reported as undefined, never as zero, when no cluster has more than one member. And all of this quantifies sampling uncertainty over the given examples, not whether those examples are representative of the real task.

Status

Open questions

  • Should --resample-unit example exist at all? It reproduces a method we have measured to be wrong. It is retained so the report can quote the cost, and because a corpus with no duplicates is entitled to it.
  • Should the near-duplicate stage's false positives widen the interval? A false near-duplicate pins two independent examples into one block and inflates the design effect. Conservative, but not free.
  • The sign-flip test is conservative on paired binary scores. An exact McNemar test on the discordant pairs would be tighter for the binary case, at the cost of a special case the graded-score path does not need.
  • A dataset card should probably print effective_n next to the row count. Milestone 11 will decide.
