Difficulty calibration

A benchmark that is all-easy or all-hard stops discriminating between systems. We estimate a transparent, model-free difficulty proxy per example so a dataset's difficulty distribution can be inspected and balanced.

Signals (documented weights)

  • input length (tokens/characters)
  • expected-output complexity (length / structure)
  • heuristic reasoning-step count
  • evidence-item count
  • tool-use requirement (from metadata)
  • ambiguity / hard tags
  • manually assigned fixture difficulty (as a sanity check)

Each DifficultyScore records the overall score, the assigned bucket (easy/medium/hard), the per-signal contributions, and the method — so the number is fully explainable.

Calibration

"Calibration" here means checking that the heuristic buckets line up with any available signal of true difficulty (manual fixture labels, or — in a future, optional mode — observed pass rates). We report the agreement; we do not claim the heuristic recovers true difficulty.

The score is a surface-feature proxy: a short prompt can be very hard and a long one trivial. Weights are hand-chosen and documented, not learned. IRT-style difficulty from real response data is a future direction.
