Milestones

The repository is built one milestone per Claude Code run via scripts/run_all_milestones_with_claude.sh. Each milestone is a coherent, committed unit; the runner verifies a new commit, a clean tree, and passing tests before the next. Each milestone updates this page's status.

Per-milestone detail

Milestone 1 — Core schemas done

Define the typed data contracts (pydantic v2) that every later stage relies on: DatasetExample, DatasetManifest, DatasetRelease, AuditResult, the finding types, SplitSpec, DifficultyScore, BootstrapResult, and DatasetCard. Round-trip (load→dump) tests lock the on-disk format. Landed in src/eval_dataset_forge/schemas.py with strict unknown-field rejection, string-valued enums for clean JSONL serialization, and cross-field validators (ratio sum, CI ordering, release/manifest count). Covered by tests/test_schemas.py — see the Schema page.

Milestone 2 — Fixture datasets done

Five small, synthetic toy datasets (qa_toy, agent_tasks_toy, retrieval_toy, bio_toy, safety_toy; 56 examples total) under datasets/fixtures/. Defects are planted on purpose — exact and paraphrase duplicates, leaked answers, train/test overlap, missing / conflicting / ambiguous / inconsistently-formatted labels, retrieval contamination — so the audits have something real to find. Each fixture ships a machine-readable defects.yaml that records the planted defects as ground truth, so later audit stages can be scored for recall rather than just “it found something”. Defects that no heuristic can catch (a well-formed but factually wrong gold answer) are marked auto_detectable: false and excluded from that recall — an explicit, documented limitation. A validation script (scripts/validate_fixtures.py) checks structural health (schema, unique ids, known families, ground-truth references), and tests/test_fixtures.py additionally verifies the planted defects are actually present. All content is synthetic and public-safe; safety “unsafe” items are SYNTHETIC-*-PLACEHOLDER strings with no operational content.

Milestone 3 — Validation & redaction done

Turns the schema into an enforced gate: required fields, type checks, ID uniqueness. Parsing is lenient so every problem across a file is reported in one pass, each addressed by record ordinal. Adds heuristic PII/secret detection (emails, phones, IPv4, AKIA… keys, PEM headers, key = value assignments, and bare high-entropy tokens) with deterministic typed-placeholder redaction whose report snippets never leak the raw value. A severity policy separates always-fatal secrets from PII warnings (promotable with --fail-on-pii). The validate CLI is wired (--json, --redact-out); a safe-data check confirms every committed fixture scans clean. See the Validation page.

Milestone 4 — Deduplication

Exact (hashing), normalized-text, and heuristic near-duplicate detection (token n-gram Jaccard; optional TF-IDF cosine with a pure-Python fallback). Tests use fixtures with known duplicate clusters.

Milestone 5 — Leakage checks

Train/test overlap, answer-in-prompt containment, high n-gram overlap against a supplied reference, and retrieval-document contamination — each producing a LeakageFinding with evidence.

Milestone 6 — Label audit

Detect missing, conflicting, ambiguous, and inconsistently formatted labels; summarize inter-annotator disagreement; export a deterministic adjudication queue. Nothing is auto-corrected.

Milestone 7 — Split builder

Construct splits with a recorded, reproducible SplitSpec: random, stratified by family/difficulty, source-grouped, and the adversarial (near-dup-aware) strategy. Re-runs leakage checks across the result.

Milestone 8 — Difficulty calibration

Compute the transparent difficulty proxy from documented surface signals, bucket it, and report the per-dataset and per-split difficulty distribution.

Milestone 9 — Statistics & ranking stability

Bootstrap confidence intervals, paired system comparison, ranking stability under resampling and example removal, and explicit small-N / instability warnings. Demonstrated on synthetic fixture system scores.

Milestone 10 — Release builder

Package a versioned release directory: validated examples, manifest with content hashes, split files, audit summary, and a REPRODUCE.md.

Milestone 11 — Dataset card generator

Render a dataset card (Markdown, optional HTML) directly from the audit and manifest, so its "known issues" always match what the pipeline found.

Milestone 12 — Smoke audit & results

Run the whole pipeline over every fixture, fully offline, and write the outcome to results/ and docs/RESULTS.md. This is the end-to-end proof that duplicates, leakage, and label conflicts are detected.

Milestone 13 — Integration contracts

Document how downstream projects consume audited releases, without taking a dependency on any of them. See the Roadmap.

Milestone 14 — Final portfolio report

Bring README and docs to portfolio quality: problem, architecture, example audit, detected issues, dataset-card example, reproduction commands, limitations, and the research path.

Milestone 15 — Final cleanup

Run the full gate — tests, lint, fixture validation, smoke audit, release build, report generation — and a hygiene scan (no secrets, no private data, no large files, no caches, no paid-API output). Verify a clean tree. Nothing is pushed.
