Milestones

The repository is built one milestone per Claude Code run via scripts/run_all_milestones_with_claude.sh. Each milestone is a coherent, committed unit; the runner verifies a new commit, a clean tree, and passing tests before the next. Each milestone updates this page's status.

Per-milestone detail

Milestone 1 — Core schemas done

Define the typed data contracts (pydantic v2) that every later stage relies on: DatasetExample, DatasetManifest, DatasetRelease, AuditResult, the finding types, SplitSpec, DifficultyScore, BootstrapResult, and DatasetCard. Round-trip (load→dump) tests lock the on-disk format. Landed in src/eval_dataset_forge/schemas.py with strict unknown-field rejection, string-valued enums for clean JSONL serialization, and cross-field validators (ratio sum, CI ordering, release/manifest count). Covered by tests/test_schemas.py — see the Schema page.

Milestone 2 — Fixture datasets done

Five small, synthetic toy datasets (qa_toy, agent_tasks_toy, retrieval_toy, bio_toy, safety_toy; 56 examples total) under datasets/fixtures/. Defects are planted on purpose — exact and paraphrase duplicates, leaked answers, train/test overlap, missing / conflicting / ambiguous / inconsistently-formatted labels, retrieval contamination — so the audits have something real to find. Each fixture ships a machine-readable defects.yaml that records the planted defects as ground truth, so later audit stages can be scored for recall rather than just “it found something”. Defects that no heuristic can catch (a well-formed but factually wrong gold answer) are marked auto_detectable: false and excluded from that recall — an explicit, documented limitation. A validation script (scripts/validate_fixtures.py) checks structural health (schema, unique ids, known families, ground-truth references), and tests/test_fixtures.py additionally verifies the planted defects are actually present. All content is synthetic and public-safe; safety “unsafe” items are SYNTHETIC-*-PLACEHOLDER strings with no operational content.

Milestone 3 — Validation & redaction done

Turns the schema into an enforced gate: required fields, type checks, ID uniqueness. Parsing is lenient so every problem across a file is reported in one pass, each addressed by record ordinal. Adds heuristic PII/secret detection (emails, phones, IPv4, AKIA… keys, PEM headers, key = value assignments, and bare high-entropy tokens) with deterministic typed-placeholder redaction whose report snippets never leak the raw value. A severity policy separates always-fatal secrets from PII warnings (promotable with --fail-on-pii). The validate CLI is wired (--json, --redact-out); a safe-data check confirms every committed fixture scans clean. See the Validation page.

Milestone 4 — Deduplication done

A three-stage ladder, disjoint by construction: sha256 exact matching on (input, expected_output); normalized-text matching (NFKC, case, punctuation, whitespace) applied to the prompt only, so a code rubric is never punctuation-folded into a different answer; and heuristic near-duplicate detection over word n-grams — pure-Python Jaccard, or idf-weighted TF-IDF cosine when scikit-learn is present, with automatic fallback recorded on every finding. A default answer gate requires candidate pairs to agree on their gold answer, which removes the two highest-scoring non-duplicates in the fixtures. Thresholds are calibrated, not asserted: a documented sweep puts both methods' knee at 0.30, where TF-IDF recovers 4 of 5 planted paraphrases and Jaccard 3 of 5, while exact recall is 4/4 with zero false positives. Two failure modes — one unreachable paraphrase and a template-question false positive — are pinned by regression tests so a future improvement cannot silently invalidate the docs. See the Deduplication page.

Milestone 5 — Leakage checks done

Four channels, each emitting exactly one LeakageKind: cross-split overlap (the dedup ladder's clusters, filtered to those spanning two splits, with each stage's certainty inherited); answer-in-prompt containment; reference n-gram overlap; and retrieval-document contamination. Unlike the dedup ladder they overlap on purpose — and it pays off: the one planted defect the ladder is provably blind to (ret-001~ret-002, a deep query paraphrase) is recovered by the passage-level check, because both examples cite the identical gold passage under different ids. Per-kind recall is 11/12; across channels, 12/12. Thresholds are calibrated: a sweep shows n=2 is the only answer-containment width that recovers both planted leaks with zero false positives, and its default threshold sits mid-plateau (weakest true positive 0.600, strongest non-leak 0.333). A label-vocabulary guard stops classification datasets from flagging every row, and prints what it ignored. Two honest negatives are documented rather than buried: the n-gram channel is redundant on these fixtures, and one reported overlap contradicts the fixture ground truth. See the Leakage page.

Milestone 6 — Label audit done

Five checks, one per LabelIssue: missing, conflicting, ambiguous, inconsistent format, and a derived adjudication flag. 15/15 auto-detectable planted label defects recovered, zero false positives. Conflict has three sources, and the third earns its keep: retrieval examples label relevance twice — as a gold doc-id list, and as flags on their own passages — so comparing the two as sets recovers ret-004 (a passage marked relevant while the gold list names none) while leaving ret-005 clean (an unanswerable query whose empty gold list is the right answer). Both carry an empty expected_output; a rule keyed on emptiness gets one of them wrong, and no other stage in the pipeline sees ret-004 at all. The one fuzzy check is calibrated against withheld ground truth: strip every ambiguous tag and the lexical heuristic recovers 4 of 6 with no false positives, with both guards shown load-bearing (dropping the wh-word guard admits "What is 2 + 2?"; dropping the scalar-gold gate admits "Name a noble gas."). The adjudication queue follows a single rule — blocking iff no resolution can be proposed — and exports byte-identically across runs. Three honest negatives are documented rather than buried: the shared-prompt conflict channel fires on nothing, the widths 4–7 "plateau" is fixture sparsity rather than a basin, and the three planted mislabeled defects are invisible to every check by construction — pinned by a regression test. See the Label audit page.

Milestone 7 — Split builder done

Five strategies over one algorithm: deal indivisible Blocks into splits until each quota is full, where the choice of block is the choice of which dependence the split refuses to cut through. Quotas are apportioned to whole examples by largest-remainder before any block moves. Every build re-runs Milestone 5's cross-split checks over its own output, so the adversarial strategy's 0.00 residual overlap on every fixture at every seed is a measurement, not a claim. Two results are worth reading twice: source-grouped closes nothing — each planted duplicate carries a fresh source_id, and on three fixtures the strategy is bit-for-bit identical to random; and joint stratification is worse on both facets than either alone, guaranteeing that no hard example reaches the test set. Consumes Milestone 6's blocking_example_ids to keep unadjudicated labels out of evaluation, and is honest that its zero is inherited from a heuristic. 723 tests. See the Splits page.

Milestone 8 — Difficulty calibration done

A transparent, model-free difficulty proxy from five documented surface signals, log-compressed so the score is dataset-independent, with score exactly the sum of its per-signal components. Three bucketings, tie-safe. Then the half that matters: a calibration harness that asks whether the proxy's ranking is distinguishable from a random ranking of the hand-assigned tags — and reports that it is not (ρ = +0.097, permutation p = 0.497, n = 51). The score is a task-family detector: task_family explains 43% of its variance and 1% of the declared label's, and the corpus's highest-scoring example is a paraphrase of FizzBuzz declared easy. Six controls make the null believable (permutation test, Bonferroni, within-family control, η² on both sides, marginal-matched accuracy, a 2000-draw weight-simplex sweep), and a positive control proves the harness can still say yes. Two results worth reading twice: the calibration target must never be a scoring signal — leaking the declared bucket in at weight 0.15 lifts ρ from +0.10 to +0.49 — which settles Milestone 7's open question by measurement; and a missing gold answer makes an example look easy, so Milestone 6's defect corrupts this stage's score. trustworthy is False, --fail-on-uncalibrated exits 1, and nothing downstream consumes the bucket as a label. 163 tests. See the Difficulty page.

Milestone 9 — Statistics & ranking stability done

Bootstrap confidence intervals, paired comparison, ranking stability under resampling and deletion, and small-N warnings — with the resampling unit as a first-class parameter rather than a hidden default. Three measured findings. The i.i.d. bootstrap is anti-conservative on any corpus with duplicates: a deterministic system scores every member of an exact-duplicate cluster identically, so the within-cluster correlation is 1 by construction, and a coverage simulation with known ground truth shows the textbook interval covering 88.2% against a nominal 95%. Resampling the duplicate blocks Milestone 7 already builds recovers 93.7%; the pooled corpus's 56 examples are worth ≈ 36 independent ones. The bootstrap "win fraction" is not a p-value — the "A wins 95% of resamples" rule has a measured type-I error of 11.4%, so the tool reports it and decides with a cluster-aware sign-flip test. Deletion beats resampling as an explanation: the demo leader's 3.6-point margin is reversed by deleting 2 of 56 examples, which turn out to be one duplicate cluster. BCa is offered and measured, and not defaulted, because it breaks the interval exactly where the data is thinnest. ranking_resolved is False, --fail-on-unstable-ranking exits 1, and the design effect is reported as a lower bound because the cluster bootstrap inherits the dedup ladder's recall. 115 tests. See the Statistics page.

Milestone 10 — Release builder done

Packages a versioned release directory: validated examples, a manifest with content hashes, split files, a re-run audit summary, and a REPRODUCE.md whose own command regenerates the bundle byte-for-byte. Adds evalforge release and evalforge verify-release.

The distinguishing work was not the packaging: a file hash answers the wrong question. It changes when the dataset does not, and holds still when the dataset's meaning moves, because re-cutting the splits leaves every byte in place. A 400-seed experiment on this repository's own corpus — data fixed, system score vectors fixed, only the split seed varying — shows the reported headline number moving with sd 0.130 against a top-two system gap of 0.036, so the test split reproduces the corpus's own ordering 48.7% of the time under random. A release therefore carries two identities (content_id, eval_id), and a pure re-split is a major version bump. It also answers Milestone 9's open question — the manifest records block structure, not effective_n, because an ICC is a property of a scored comparison and a dataset does not have one.

An early draft claimed the adversarial strategy yields a better test split; the sub-population accuracies killed it. Its higher agreement rate comes from measuring a different estimand whose true gap is nearly three times larger, not from a lower-variance estimate of the same one. The tool records split_spec and does not rank the strategies. See the Releases page.

Milestone 11 — Dataset card generator done

Renders a dataset card (Markdown, optional standalone HTML) from exactly two inputs — a release's manifest.json and its audit.json — so its "known issues" cannot drift from what the pipeline found. Nothing is recomputed: a view that recomputes its own source is not a view. Adds evalforge dataset-card and the reports/ package.

The distinguishing work was noticing that a card is an artifact of the release it describes, and hashed into manifest.hashes like any other. Two fields every dataset card in the wild carries therefore become impossible: the file-hash table (its own digest would have to appear inside its own bytes) and created_at (a clock in a hashed artifact makes Milestone 10's none version bump unreachable). Both absences are pinned by tests. The consequence is that the release builder assembles its manifest twice — once for the card to render from, once with the card's hash in it — and the two differ only in the one field build_card refuses to read.

It also answers the question Milestone 10 left open. A card saying "14 examples" about a corpus of 11 independent blocks is not lying, but a reader spends that 14 as a sample size. The card prints both, and per split — because the number that bounds a claim about a test score is the test split's block count, which is neither. manifest.dependence gained blocks_by_split to make that printable. Curator prose (purpose, construction, recommended use, non-goals) is the one thing no audit can compute: it travels in manifest.card_meta, blank sections are named rather than omitted, and rewriting one is a patch. See the Dataset card page.

Milestone 12 — Smoke audit & results done

Runs the whole pipeline over every fixture and the pooled corpus, fully offline, writes an audit.json + audit.md per dataset to results/, and scores every finding against the defects that fixture deliberately plants. Adds evalforge audit and evalforge smoke — the last two stubs in the CLI contract. 40 of 40 detectable planted defects recovered, 0 missed.

The distinguishing work was noticing that that number is worthless on its own. A detector that flags everything recovers every planted defect, and scores recall 1.000 — exactly what the pipeline scores. No matching rule repairs it; subset, exact-set, and pairwise matching all award the degenerate detector full recall, because full recall is what it has. So the flag-everything control ships inside the report, scored on every run, and every recall is printed beside a precision (which separates them by 9× to 190×).

That forced a second decision. A duplicate finding is a cluster, and a cluster is a conjunction of assertions, not one assertion: k members assert k(k−1)/2 pairs. Scored per-cluster, one 14-member cluster is "correct"; scored per-pair, its precision is 0.033. The decomposition earns its keep on real output too — qa_toy's near stage merges {qa-003, qa-004, qa-012} and thereby asserts qa-004 ≈ qa-012, which nothing plants and which no cluster-level view would ever show. And because a recall's denominator is chosen by the same people who wrote the detectors, all five excluded planted defects are listed by id with which of two distinct reasons excluded them, and the recall over every planted defect (0.909) is printed beside the 1.000.

Running the pooled corpus — audited but deliberately unscored — turned up a result none of the per-fixture audits can see: a near-duplicate verdict is a property of a pair and its corpus. TF-IDF's IDF term is computed over the collection, so sim(saf-004, saf-007) moves from 0.287 to 0.344 across the 0.30 threshold when safety_toy is pooled with the other four fixtures — neither prompt changed. Deduplication is therefore not composable. Finally, audit.md — listed in the plan since Milestone 0, shipped in no release until now — completes the evidence bundle. See the Results page.

Milestone 13 — Integration contracts

Five downstream projects, five executable contracts, one new command: evalforge gate --release … --profile llm-regression. A gate needs an opinion an audit does not have, so the policy lives with the consumer; and it needs a third verdict, because a boolean gate that maps leakage_flags == [] → pass converts Milestone 12's vacuous zeros into permission. undecidable never passes unless a policy says so in writing.

Writing the contracts down measured three things nothing earlier had stated. The scikit-learn that docs/PLAN.md calls an "optional accelerator" is a different detector: rebuilding bio_toy from identical bytes, an identical command and an identical seed yields the same content_id and a different eval_id when the package is absent. REPRODUCE.md claimed determinism "given the same inputs and seed" — the environment is an input, and every release now records the method that ran. verify-release touches no detector, so verification is environment-independent where reproduction is not.

The other two are consequences of idf being computed over the collection. A gate verdict is not preserved under union: safety_toy passes a one-cluster near-duplicate budget alone and the same ten rows fail it beside four fixtures that share no duplicate with them. And independent-block count is not additive though example count is — 45 blocks apart, 44 pooled, at 56 examples either way, with zero cross-fixture duplicate edges. Under the jaccard fallback both properties hold, so composability is a property of the similarity function and the optional dependency is what removes it. All five profiles reject the release built from the deliberately flawed qa_toy fixture, which is the only correct answer. See Integration contracts.

Milestone 14 — Final portfolio report landed

README and docs brought to portfolio quality — problem, architecture, a worked example audit, what the pipeline finds, a dataset-card example, reproduction commands, limitations, and the research path — and then the prose was audited by the repository.

The reason is Milestone 13's own correction. It measured that a release is not reproducible from its inputs and seed alone, because the build environment is an input, and it fixed the sentence that said otherwise in exactly one place: REPRODUCE.md, which is generated and pinned by a test. The identical false sentence survived untouched in README.md, docs/METHODOLOGY.md and docs/PLAN.md — three files no test had ever read. A generated artifact is enforced; prose is not.

scripts/verify_docs.py runs ten checks: links resolve, every documented evalforge command names a real subcommand and real options against the live parser, every cited test count is what pytest collects, every cited fixture id exists, no live document asserts a retired claim, and every number in docs/CLAIMS.md is reproduced by the command the ledger says produces it. Two results came out of it. A number is not a claim until it names the command that produced it: the qa_toy calibration p-value is 0.789 under evalforge difficulty and 0.777 under evalforge audit — same fixture, same seed, same statistic, different --resamples default, and both correct. And two published figures had no command that could produce them: the Jaccard block counts required uninstalling scikit-learn, so audit --near-method {auto,tfidf,jaccard} now pins the detector. A phrasing lint that could not separate a claim from its correction was measured at precision 0/2, recall 0/1, and ships registered but disabled — the same treatment Milestone 13 gave difficulty_is_calibrated.

Milestone 15 — Final cleanup

Run the full gate — tests, lint, fixture validation, smoke audit, release build, report generation — and a hygiene scan (no secrets, no private data, no large files, no caches, no paid-API output). Verify a clean tree. Nothing is pushed.
