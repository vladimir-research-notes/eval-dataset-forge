Milestone 6 — done

Label audit & adjudication

Label noise caps any accuracy a benchmark can measure and biases every comparison drawn from it. This stage surfaces label defects and queues the ones a machine cannot resolve for a human. It never rewrites a label.

Five checks

Each public check emits exactly one LabelIssue — a property the tests enforce, along with the converse: no kind is declared in the schema without a check that can emit it.

checkcertaintycatchesrecall
missingexactno gold answer to score against4 / 4
conflictingexacttwo label sources that disagree4 / 4 annotators · 1 / 1 relevance
ambiguousmixedmore than one defensible answer5 / 5 declared · 4 / 6 lexical
inconsistent formatheuristica gold answer unlike its family's2 / 2
needs adjudicationderivedan issue only a human can resolve—

15 / 15 auto-detectable planted label_issues recovered, 0 false positives across the five fixtures (56 examples, 16 flagged, 14 blocking). The relevance conflict is counted separately because retrieval_toy files it under relevance_issues rather than label_issues; the lexical ambiguity figure is what the heuristic finds with every declaration withheld.

Ambiguity is mixed because it fuses two things: an ambiguous entry in difficulty_tags is an exact reading of a declaration, while the underspecified-prompt and open-set-request signals are lexical heuristics. Every finding's detail records which signal fired.

Stage order is load-bearing, unlike the leakage channels. missing runs first: an absent answer has no format, and must not enter the shape census the format check measures every other answer against.

Deeper: three ways two labels disagree

A conflict is not a wrong label. It is two label sources that cannot both be right — a strictly weaker and strictly checkable claim.

  1. Annotators of one example. The finding records whether a strict majority exists, because that decides whether a human must look at it. All four planted conflicts are 2-annotator ties, so none resolves automatically.
  2. Two examples, one prompt. Consumes dedup.duplicate_input_clusters, the superset the deduplication ladder exposes precisely so this stage can take the difference: a shared prompt with an identical answer is a duplicate to drop; with a differing answer it is a conflict to adjudicate. On these fixtures the difference is empty — all four shared-prompt clusters are true duplicates. An honest null result, asserted by a test and exercised by a synthetic pair.
  3. One example, two relevance channels. Retrieval examples label relevance twice — as a gold doc-id list, and as relevant flags on their own passages. Two encodings of one quantity, so they can contradict each other.

The check that distinguishes two look-alikes

Both ret-004 and ret-005 carry an empty expected_output. A rule keyed on emptiness flags both — and would be wrong about one of them.

examplegold listpassages marked relevantverdict
ret-004[]{d9}conflict — an incomplete relevance set
ret-005[]{}clean — an unanswerable query, correctly labelled

Comparing the two channels as sets separates them with no special case: an empty gold list agreeing with zero relevant passages is agreement, not an absence. ret-004 is the planted incomplete_relevance defect, and no other stage in the pipeline sees it.

Deeper: calibrating the ambiguity heuristic

A declaration is exact and free. The question a real dataset poses is the one where nobody has tagged anything: would we have found these without being told? Withholding every ambiguous tag from all 56 examples:

Widths 4–7 agree, but that is a sparsity plateau, not a robustness basin: no fixture prompt of 5–7 tokens passes the guards. The default is therefore the smallest width attaining full reachable recall, not the middle of a basin we have evidence for.

Both guards are load-bearing

Two signals fire — a dangling reference (≤ 4 tokens, no wh-word) and an open-set request ("Name a primary color.") — and both are gated on a scalar gold answer. Each guard prevents exactly one false positive:

  • Drop the wh-word guard and qa-005 ("What is 2 + 2?") is called ambiguous.
  • Drop the scalar-gold gate and ret-004 ("Name a noble gas.") is called ambiguous.

The second is the interesting one. qa-008 ("Name a primary color.") and ret-004 ("Name a noble gas.") are the same sentence pattern; the fixture declares the first ambiguous and not the second. No rule keyed on prompt text alone can separate them. What does separate them is the shape of the gold answer: a list-valued answer can enumerate every acceptable response, so an open-set prompt answered by a set is not under-specified. A test swaps only the answer shape between the two prompts and shows both verdicts flip with it.

What it cannot reach

The heuristic recovers 4 of 6 declared-ambiguous examples. The two misses define the ceiling: saf-007 is a dual-use request whose ambiguity is a semantic judgement, and ret-005 is over-specified rather than under-specified. Declared ambiguity and detectable ambiguity are different sets; the audit reports their union and names the signal.

Deeper: format, and inter-annotator agreement

Within a task family: a shape minority (a bare string among rubric dicts — agent-011) and a vocabulary outlier ("no" among comply/refuse — saf-010, reusing Milestone 5's label_vocabulary). Shape, not key set: the agent fixture's coding tasks carry {reference_solution, success_criteria} and its research tasks {reference_answer}, a legitimate per-subtype schema a key-set check would call three defects. Both signals self-disable — the vocabulary is empty on every free-text family, and a family with no dominant shape gets no shape check.

Agreement is reported as a raw rate over multiply-annotated examples, not a chance-corrected coefficient. It is None, not 0.0, when undefined — those mean opposite things. On the fixtures it is 0.0, an artifact of construction: annotations were planted only where a conflict was planted. A test asserts the number so it can never be quoted as if it described a real annotation process.

Adjudication queue

One rule: an example is blocking exactly when at least one of its issues has no resolution the audit can propose. Nothing else is special-cased.

issueproposed resolution
missingnone — the tool does not know the answer
ambiguousnone — the tool cannot decide which answer was meant
conflictingthe strict-majority annotator label, when one exists
inconsistent_formatconvert to the family's dominant shape or vocabulary

A relevance conflict blocks even though "copy the flags into the gold list" looks like an obvious fix: it is equally possible that the flag is wrong, and guessing would silently rewrite the benchmark. Of the 16 queued fixture examples, only 2 are non-blocking.

Nothing is applied — a proposal is a string in a queue, never an edit. The queue is deterministic (blocking first, then severity, then example_id) and exports as one compact JSON object per line, so two runs produce byte-identical adjudication_queue.jsonl files and a reviewer's resolutions diff cleanly.

The blind spot that matters most. This stage sees structure, never truth. Three mislabeled defects are planted and marked auto_detectable: false: qa-006 (the chemical symbol for gold given as Ag), bio-009 (23 chromosomes in a human somatic cell), and saf-006 (a benign vaccine question labelled refuse). All three are well-formed, unanimous, unambiguous and correctly shaped, and none is found by any check — a regression test asserts they stay invisible. A mislabeled answer that looks like every other answer is precisely the label defect that does the most damage to a benchmark. Catching it needs a second annotator or a model.

Status

Complete. 144 tests pass; 522 across the suite. There is no evalforge label-audit subcommand — the label audit surfaces through evalforge audit (Milestone 12), keeping the CLI contract stable.

Open questions

  • At max_tokens=8 the heuristic flags bio-004, which the ground truth files under conflicting. Its annotators split on drug vs chemical compound — arguably because the prompt never says which taxonomy. That reading makes it a true positive under a different heading. Scored conservatively as a false positive; the default width is not tuned on it either way.
  • retrieval_toy plants no label_issues; its two findings map onto the relevance_issues block instead. Counted as recovered under a different heading, not as false positives — but the taxonomy seam is worth a human's eye.
  • The format thresholds (70% dominant share, 4 examples, 3 repeats) are judgement calls. Each is guarded by a test showing what it prevents, but there is only one planted defect per signal, so a calibration sweep would be degenerate.
