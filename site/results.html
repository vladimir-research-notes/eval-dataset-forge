M13

Results

The smoke audit runs the entire pipeline over every fixture, fully offline. Because the fixtures are hand-authored with deliberate defects, the audit's job is to rediscover the planted defects.

Every number on this page is measured in sample. These fixtures' defects were planted by the same repository that wrote the detectors, and the near-duplicate and answer-in-prompt thresholds were selected by sweeps over these same fixtures. Recall here is a resubstitution estimate: it says the pipeline finds what it was built to find, on the data it was built against. It does not estimate performance on a corpus this repository has not seen. There is no held-out corpus, and saying so is cheaper than implying otherwise by silence.

The headline, and why it is not the recall

40 of 40 detectable planted defects recovered, 0 missed, 5 unexplained assertions across 56 examples. That number, alone, is worthless — and the smoke audit proves it by scoring a detector that flags everything under the identical rule:

detectorrecallprecision (dedup.exact)precision (labels.missing)
the pipeline1.0001.0001.000
flag every example and every pair1.0000.0140.071

Recall is maximized by asserting everything, so it bounds what a detector misses and says nothing about what it invents. No matching rule repairs this: subset matching, exact-set matching, and the pairwise rule all award the degenerate detector full recall, because full recall is what it has. So every recall is printed beside a precision, and the degenerate control ships inside the report rather than in a footnote.

Source-grouped closes nothing. Every planted duplicate carries a fresh source_id (src-fr-capital → src-fr-capital-dup), exactly as a real corpus records a paraphrase written as a new record — and on the three fixtures where no source is shared at all, the strategy produces a bit-for-bit identical assignment to random. The default is a single facet. The label audit recovers 15 of 15 auto-detectable planted label defects with zero false positives — and is blind, by construction, to the three planted mislabeled answers (qa-006, bio-009, saf-006), which are well-formed, unanimous, unambiguous and correctly shaped. That blindness is asserted by a regression test rather than left implicit: label truth needs a second annotator or a model.

Across all four leakage channels, 12 of 12 planted leakage defects are recovered — including ret-001~ret-002, which the dedup ladder is provably blind to and which the passage-level check finds anyway. Per-kind, recall is 11 / 12. Full analysis in docs/LEAKAGE.md and docs/DEDUPLICATION.md.

Difficulty calibration M8

This stage is not scored against defects.yaml either — no ground-truth difficulty is planted, only the tags the fixtures' author wrote down. So it is scored against a falsifiable question: is the heuristic's ranking distinguishable from a random ranking of those declared labels? Over the 51 labelled examples of the pooled corpus, it is not.

The difficulty heuristic is a task-family detector. Its dominant axis is length; length separates task families; and declared difficulty is nearly orthogonal to task family. The highest-scoring example in the corpus is agent-002, a paraphrase of FizzBuzz declared easy. Of the five signals, tool_use fires on 0 of 56 examples and is reported inert; output_complexity and evidence_items are anti-correlated with declared difficulty; and input_length alone clears α (p = 0.043) but not Bonferroni over the four testable signals (p = 0.174).

The calibration target must never be a scoring signal. An earlier design used the hand-assigned difficulty as both an input to the score and the check on it. Blending it back in at weight 0.15 lifts ρ from +0.10 to +0.49 — a null heuristic reading as a working one. This also settles Milestone 7's open question by measurement: stratifying on the heuristic bucket would have stratified on task_family a second time, under a different name.

A missing gold answer makes an example look easy. An absent expected_output scores zero on output_complexity, so agent-009 ranks 1 of 56 and qa-010 ranks 2 of 56 — both MISSING findings from Milestone 6. The previous milestone's defect corrupts this one's score, and the report warns rather than imputing.

Consequently trustworthy is False on every fixture and on the pooled corpus, and evalforge difficulty --fail-on-uncalibrated exits 1. That is the intended outcome. The harness is not merely pessimistic: a synthetic corpus whose difficulty genuinely is surface-driven returns ρ > 0.9 and trustworthy = True. Full analysis in docs/DIFFICULTY.md.

Statistics & ranking stability M9

This stage has no planted defect to rediscover, and its system scores are synthetic (no model runs offline). So it is scored the only way a statistical method can be: against known ground truth in simulation — does a 95% interval contain the true parameter 95% of the time? 3000 trials, B = 999, on 44 blocks with the pooled corpus's exact size profile.

true accuracyi.i.d. bootstrapcluster bootstrapcluster + BCa
0.500.9040.9440.954
0.700.8820.9370.956
0.900.8470.8840.947

On genuinely i.i.d. data the same percentile interval covers 0.954 — the positive control that makes the rows above a finding rather than a broken harness.

A duplicate cluster is not one example, and the textbook bootstrap counts it as one. A deterministic system scores every member of an exact-duplicate cluster identically, so the within-cluster correlation is 1 by construction. On the pooled corpus the measured design effect is 1.39–1.56 (Kish's closed form predicts 1.50), CIs widen 1.16×–1.29×, and 56 examples are worth ≈ 36 independent ones. Simulating the same blocks with zero within-block correlation returns a design effect of 1.0, so the widening tracks the dependence and not the choice of unit.

The bootstrap "win fraction" is not a p-value. Under a true null (n = 56, two Bernoulli(0.7) systems), the rule "A beats B if A wins ≥ 95% of resamples", read in whichever direction the data favours, rejects 11.4% of the time against a nominal 5% — a one-sided threshold used two-sidedly. The corresponding 0.975 threshold measures 0.057. The tool reports the win fraction and decides with a cluster-aware sign-flip test, which measures 0.029: conservative, because paired binary differences are mostly ties.

One duplicate cluster decides the demo leaderboard. sys_a leads sys_b by 3.6 accuracy points. Deleting 2 of 56 examples reverses it — and those two, agent-005/agent-006, are a single near-duplicate cluster. A mechanism, not a coincidence: a cluster of size m contributes m times to a margin while carrying one item's worth of information. The margin's 95% CI is [−0.185, +0.264], the leader holds first place in 63.2% of resamples, and detecting a gap that size would need ≈ 4500 examples. ranking_resolved is False, and --fail-on-unstable-ranking exits 1.

BCa is offered and not defaulted, because it is not uniformly better: it repairs the clustered interval at an extreme accuracy (0.884 → 0.947 at p = 0.90) and breaks the i.i.d. one (0.926 → 0.830 at p = 0.95), where 5.7% of trials cannot compute the bias correction and fall back — reported as bca->percentile rather than silently relabelled. Two limits are inherited: the cluster bootstrap corrects only for dependence the dedup ladder can see, so the design effect is a lower bound; and the demo's systems are simulated. Full analysis in docs/STATISTICS.md.

Release identity M10

Is a dataset's content enough to identify a release? No. Hold the corpus fixed, hold each system's per-example score vector fixed, and vary only the split seed. Anything that moves is caused by the split — which is exactly what a content hash cannot see. Pooled corpus: 56 examples, 44 independent blocks, 3 simulated systems, 400 seeds per strategy.

quantityvalue
distinct content_id across 400 seeds × 3 strategies1
full-corpus gap, sys_a − sys_b+0.0357

P(test reproduces the corpus ordering of the top two)0.487
leader by seedsys_a 186 · sys_b 128 · sys_c 8 · tie 78

The split seed is worth 3.6× the effect the benchmark measures. The mean over seeds recovers the corpus number (0.7011 vs 0.6964), so this is variance, not bias. Hence two identities in the manifest — content_id (are these the same examples?) and eval_id (are two scores comparable?) — and hence a pure re-split is a major bump.

A claim the measurements killed: an early draft credited the adversarial strategy with a better test split, citing its 65.0% agreement rate against random's 48.7%. But adversarial evicts duplicate clusters from dev/test, and both systems score higher on duplicated examples (0.750/0.700) than on singletons (0.667/0.639). Its test set measures a sub-population whose true gap is nearly three times larger (+0.1029 vs +0.0357) — a different estimand, not a better estimate of the same one. The tool records split_spec and does not rank the strategies. See Releases.

Smoke audit — scoring the scorer M12

Every stage above scored itself against defects.yaml by hand. This milestone runs the whole pipeline over every fixture and does that scoring in code — which forced the question the hand-written tables never had to answer: what is a correct scoring rule for a defect detector?

A cluster is a conjunction of assertions, not one assertion. Duplicate findings are clusters. Score a cluster as one prediction and you must choose between two wrong rules: count it correct if it contains a planted pair, and one 14-member cluster is "correct"; count it correct only if it equals a planted pair, and a true 3-member cluster covering a planted pair is "wrong". A cluster of size k asserts all k(k−1)/2 of its pairs, so that is the unit both recall and precision are counted on.

This is not bookkeeping. On qa_toy the near stage emits one cluster, {qa-003, qa-004, qa-012}. It thereby asserts qa-004 ≈ qa-012 — a pair nothing plants, and which no cluster-level view would ever show. Pair decomposition surfaces it as the channel's one unexplained assertion and drops its precision to 0.571.

Channel by channel the pipeline's precision is 9× to 190× the control's, and the gap is widest on the pair channels for a structural reason: a flag-everything detector must assert all C(n,2) pairs but only n examples, so its pair precision falls as 1/n² and its example precision only as 1/n. precision is kind-specific and is n/a where the fixtures plant nothing of that kind — 0.0 would then be the only value any non-silent detector could score.

The denominator is chosen by the authors of the detectors. 45 defects are planted; 40 enter the recall denominator. The five that do not are listed by id, with which of two different reasons excluded them: not-auto-detectable is the fixture's declaration that no heuristic here should find it (three mislabeled answers); no-channel is a fact about the scorer — this project wires no detector to that ground-truth kind (paraphrased_documents). Collapsing the two would let a missed defect be reclassified as an out-of-scope one. Recall over every planted defect, refusing all exclusions, is 0.909, and the report prints it beside the 1.000. An unmapped ground-truth kind raises rather than being skipped: a planted defect must not leave the denominator by typo.

Corroboration across channels is not a false positive. The n-gram check flags qa-002 — planted as half of an exact_duplicates pair. The retrieval check flags ret-001/ret-002 — planted as a duplicate_documents pair. The scorer projects ground truth into the channel's unit and counts those as explained. The projection preserves the unit, which stops it becoming a blanket pardon: qa-004 and qa-012 are each planted, their pairing is not, so it stays unexplained. Corpus-wide there are exactly five unexplained assertions; four were already documented as disputed in M4–M5, and the fifth (ret-005) is a gap in the ground truth, flagged for human review rather than settled by editing defects.yaml.

A near-duplicate verdict is not a property of a pair — it is a property of a pair and its corpus. The pooled audit finds one duplicate cluster the per-fixture audits do not, and it is not a cross-fixture one: {saf-004, saf-005, saf-007} lies entirely inside safety_toy. sim(saf-004, saf-007) is 0.2866 alone and 0.3438 pooled, straddling the 0.30 threshold — neither prompt changed. TF-IDF's inverse-document-frequency term is computed over the document collection, so the boilerplate the two safety prompts share is common inside safety_toy and rare against the wider pooled vocabulary, and rarer means heavier. Consequences: deduplication is not composable (auditing shards and unioning the findings is not auditing the union), and appending unrelated examples can create duplicate clusters among examples that did not change — which, because the adversarial split builder derives blocks from those clusters and eval_id folds the split in, can move an untouched example's split and change a release's eval_id. Flagged for review; the Jaccard fallback has no IDF term and is presumably immune, which is not yet measured.

Integration contracts M13

Writing the five downstream contracts measured three things the pipeline had not stated. Full argument: Integration contracts.

1. The "optional accelerator" is a different detector. Rebuilding bio_toy from identical bytes, an identical command and an identical seed:

content_id holding is correct; eval_id moving is the tool telling the truth. What was false was REPRODUCE.md, which claimed determinism "given the same inputs and seed". The environment is an input, and the file now says so. verify-release runs no detector, so it still passes 10/10 without the accelerator — verification is environment-independent; reproduction is not.

2. Neither block counts nor gate verdicts survive a union. The five fixtures are disjoint and share no example:

examplesindependent blocks
audited separately, summed (tfidf)5645
audited as one corpus (tfidf)5644
audited as one corpus (jaccard)5646

The pooled corpus contains zero cross-fixture duplicate edges: merging five unrelated datasets found no duplicate between them and still changed one dataset's verdict inside itself. Correspondingly, safety_toy alone passes a max_near_duplicate_clusters: 1 policy and the same ten rows fail it inside the pooled corpus. Under jaccard, which has no idf, both counts agree. Example count is additive; statistical power is not.

Nor does a verdict survive a re-split, for four of the fourteen requirements — a bug in this milestone's own first draft, caught by checking a docstring instead of shipping it. Building qa_toy forty times with --strategy random, all forty releases share one content_id; seeds 9 and 35 pass eval_splits_deduplicated and thirty-eight seeds fail it. GateReport.scope is now eval_id whenever a split-sensitive requirement ran.

3. A gate needs a third verdict. pass / fail / undecidable, and undecidable never counts as a pass. no_retrieval_contamination is undecidable on qa_toy because no example carries passages — a fact about the corpus. difficulty_is_calibrated is undecidable on every release this tool has built, because audit.json keeps the three difficulty bucket counts and drops the permutation test that says whether they mean anything — a fact about the release format. Milestone 11's review note already asked whether that field should exist; the contract makes the gap executable and gives it a second cost.

All five profiles reject the release built from the deliberately flawed qa_toy fixture. A gate that passed it would be broken; the positive control is a --drop-repaired release that passes.

Auditing the documentation M14

Every stage above audits a dataset. This one audits the prose, and Milestone 13 supplied the reason by accident: it measured that the build environment is an input, corrected the sentence that said otherwise in the one file that was generated and test-pinned, and left the identical false sentence in README.md, docs/METHODOLOGY.md and docs/PLAN.md. A generated artifact is enforced; prose is not. Full method: Claims.

A number is not a claim until it names the command that produced it. Same fixture, same seed, same statistic (ρ = −0.080), two published p-values — and both are correct:

command--resamples defaultpermutation p
evalforge difficulty100000.789
evalforge audit20000.777

The gap is the permutation test's Monte-Carlo error. So each of the 11 registered claims carries the command that produces it, and that column is itself checked. It caught a claim citing evalforge audit --near-method jaccard — a flag nobody had built — which is how this milestone found that the Jaccard figures published since Milestone 4 could only be reproduced by uninstalling scikit-learn. The flag now exists.

A phrasing lint cannot separate a claim from its correction. The candidate rule sklearn_is_an_accelerator, run over the live docs as this milestone found them, flagged LIMITATIONS.md and RESULTS.md — which quote the claim in order to refute it — and missed PLAN.md §3, which asserted it. Precision 0/2, recall 0/1. It ships registered and disabled, the treatment Milestone 13 gave difficulty_is_calibrated.

A checker reporting zero violations is indistinguishable, on that number alone, from a checker that looks at nothing — the mirror image of the flag-everything control above. So tests/test_docs.py plants a defect for every check and asserts the check fires. Both false positives the auditor ever produced were use/mention errors, and both are pinned by tests.

Status

Every stage is implemented and every number above is reproducible offline from the committed fixtures. The full run is evalforge smoke; the summary it writes is results/reports/smoke_audit.md (gitignored — it regenerates byte-for-byte, and carries no timestamp). See docs/RESULTS.md.

Milestone 15 ran the whole gate clean — 1852 tests, ruff, fixture validation, smoke, the demo-release rebuild, and the documentation auditor — and closed two gaps it exposed: an adapters/ package the architecture diagram named but no one built (now caught by the eleventh documentation check), and a hygiene scan (scripts/hygiene_scan.py) the safety docs referenced but did not ship. Rebuilding the committed qa_toy release without scikit-learn preserves content_id, eval_id, and every split byte — only the artifacts that name the detector move.
