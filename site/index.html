Make evaluation datasets trustworthy

A benchmark that reports one accuracy number hides most of what decides whether that number means anything. eval-dataset-forge turns duplication, leakage, label noise, split artifacts, difficulty imbalance, and unstable rankings into measured, reported properties of a dataset.

The problem

Two systems can be separated by a gap that vanishes under resampling. A "hard" test set can be trivially solved because the answer leaks into the prompt. A five-point gain can be an artifact of forty near-duplicate examples clustered in the test split. These are common, documented failure modes — and they are invisible in the JSONL file itself.

The idea

A benchmark dataset should not be a bare file. A trustworthy release is a dataset + evidence bundle:

1. Schema validation

Typed fields, ID uniqueness, metadata consistency.

2. Deduplication

Exact, normalized, and near-duplicate detection.

3. Leakage checks

Train/test overlap, answer-in-prompt, n-gram & retrieval contamination.

4. Label audit

Missing, conflicting, ambiguous, and inconsistent labels, plus an adjudication queue.

5. Difficulty calibration

Transparent, model-free difficulty proxy + distribution — and a permutation test that says whether the proxy means anything.

6. Split rationale

Random, stratified, source-grouped, adversarial, temporal.

7. Statistical uncertainty

Bootstrap CIs, paired comparison, ranking stability.

8. Dataset card + manifest

Purpose, known issues, non-goals, hashes, reproduce commands.

Architecture

raw examples → validate → dedup → leakage → label-audit → difficulty
             → splits → statistics → report → versioned release

Each stage is a separable, independently tested module. The pipeline is deterministic given a fixed input and seed, runs fully offline, and needs no GPU and no paid API.

Design constraints

  • CPU-first; runs on a general instance (e.g. m5.2xlarge).
  • Fully offline by default; no paid API anywhere in this version.
  • Small, honest dependency set (pydantic, numpy, pyyaml) with pure-Python fallbacks for optional accelerators.
  • Privacy-safe synthetic fixtures; redaction + PII-like detection built in.
  • Every heuristic documents its failure modes.

Status

The scaffold, plan, CLI, website, environment check, milestone runner, and CPU-only test suite are in place; the typed data contracts every stage builds on — the pydantic v2 schema models — landed in Milestone 1; Milestone 2 added five synthetic fixture datasets with deliberately planted defects and a machine-readable ground-truth file per fixture, so the audit stages can later be scored for recall against known defects; Milestone 3 landed the first pipeline stage — validation & redaction (schema, ID uniqueness, PII/secret detection, and typed-placeholder redaction), wiring the evalforge validate command; Milestone 4 added the second — deduplication, a three-stage exact / normalized / heuristic ladder whose near-duplicate thresholds are calibrated against the fixtures' planted paraphrases and whose two failure modes are pinned by regression tests; and Milestone 5 added the third — leakage & contamination, four deliberately non-disjoint channels (cross-split overlap, answer-in-prompt containment, reference n-gram overlap, retrieval contamination) that between them recover every planted leakage defect, including one the deduplication ladder is provably blind to; Milestone 6 added the fourth — the label audit, five checks plus a deterministic adjudication queue, honest that label truth is invisible to all of them; Milestone 7 landed the first stage that changes the data rather than describing it — the split builder, whose five strategies share one algorithm and differ only in which dependence between examples they refuse to cut through, and which verifies every build by re-running the leakage checks over its own output; Milestone 8 added difficulty calibration — a transparent surface proxy, and a permutation test that falsifies it: on these fixtures the proxy's ranking is indistinguishable from a random ranking of the declared difficulty tags, because what it really measures is task family. The score ships, reported and explicitly uncertified. Milestone 9 added statistical uncertainty & ranking stability, which turns the deduplication report into a correction: a coverage simulation with known ground truth shows the textbook i.i.d. bootstrap covering 88.2% against a nominal 95% on a corpus with duplicate clusters, so the intervals resample blocks instead, the widely-reported "win fraction" is shown not to be a p-value (11.4% type-I error), and the demo leaderboard is reversed by deleting one duplicate cluster. Milestone 10 landed the release builder — a versioned bundle with a manifest, a re-run audit, and a REPRODUCE.md that regenerates it byte-for-byte — carrying two dataset identities, because holding the data fixed and varying only the split seed moves the reported headline number with sd 0.130 against a top-two system gap of 0.036, which a content hash cannot see. Milestone 11 generates the dataset card from the manifest and the audit, so its "known issues" cannot drift; because the card is itself a hashed artifact of the release, it can print neither a file-hash table nor a build timestamp, and it reports the corpus as 14 examples in 11 independent blocks rather than letting a reader spend 14 as a sample size. Milestone 12 ran the whole pipeline over every fixture and scored the scorer: a detector that flags everything earns recall 1.000 under the identical rule, so every recall here is printed beside a precision and the degenerate control ships inside the report. Milestone 13 wrote executable integration contracts for five downstream consumers, all of which reject the deliberately flawed demo release — and found that the "optional accelerator" scikit-learn is a different detector, so the build environment is an input. Milestone 14 turned that discovery on the repository itself: the corrected sentence had been fixed only in the one file a test could read, so the documentation is now audited by the repository, with every published number bound to the command that produces it. See Milestones and the docs/PLAN.md build contract.

This is a benchmark-quality instrument, not a certifier of universal benchmark quality and not a medical, legal, or security authority. See Limitations.
